## Consolidated review (synthesis)

# DQF N6b Design Review -- Executive Summary

**The architectural direction is sound, but the design is not ready to implement as written.** Separating eligibility from ranking and replacing substring matching with curated mappings are appropriate foundations. The proposed scoring semantics and safety boundary still permit unsafe recommendations.

The top three risks are:

1. **False comparability and fabricated efficacy.** Cross-endpoint fallbacks, neutral scores for missing evidence, and endpoint-key matching can produce unjustified winners. Comparable evidence requires aligned outcomes, populations, comparators, horizons, doses, and units—not merely a shared condition.
2. **Incomplete safety enforcement.** Condition-local contraindications and insufficient patient inputs can bypass hard gates. Legacy requests and combination suggestions remain additional recommendation paths outside the proposed boundary.
3. **Premature release of misleading rankings.** Unsafe taxonomy equivalences, residual mechanism-scoring errors, and unvalidated transforms survive eligibility filtering. The phased rollout exposes incomplete scoring while leaving ordinary UI users on the legacy path.

Before implementation approval, correct the taxonomy; distinguish eligibility, safety-assessment completeness, and rankability; prohibit mixed-endpoint rankings and missing-evidence imputation; define sourced safety rules and typed evidence contracts; and close every recommendation-path bypass. Finalize versioned API contracts and a joint safety/calibration/UI release gate.

Start with an evidence-readiness audit and one fully supported clinical objective, not mandatory coverage of all 95 drugs. Unsupported or insufficiently evidenced drugs should have explicit dispositions without invented scores.

The supplied reviews also identify several server defects already fixed; these should not remain implementation prerequisites. Dataset completeness, UI compatibility, and the 352-query grid remain unverified.

# Verdict

**Not ready to implement as specified.** Approve the eligibility-first architecture, not the current clinical semantics or rollout.

First, suppress unsafe recommendations across legacy and downstream paths and conduct an evidence-readiness audit. Then revise the design around one supported objective: corrected taxonomy, sourced contraindications with required patient inputs, compatible typed evidence, calibrated scoring, explicit unranked/unknown states, and versioned API/UI handling.

Remove mixed-endpoint fallbacks and neutral efficacy imputation before approval. Release safety gates and validated ranking together, with tests proving that excluded or insufficiently assessed drugs cannot reappear as recommendations.

Broader coverage and generalized rule machinery can wait. Essential safety inputs, clinical sourcing, and evidence compatibility cannot. Existing server fixes should be reflected accurately; claimed dataset, UI, and grid coverage still requires verification.

## Verdict

**Not ready to implement as specified.** The eligibility-first architecture and explicit curated indication mappings are sound foundations, but the ranking design still permits the failures it claims to eliminate.

Before implementation, remove per-drug cross-endpoint fallbacks and neutral-score imputation; separate clinical eligibility from evidence-based rankability; correct the taxonomy; and define typed, sourced endpoint contracts with comparator, horizon, population, dose, and units.

Resolve the three flat-5.0 classes through evidence validation—not merely new branches. Diabetes needs a coordinated typed migration; hypertension needs a comparability audit; anticoagulation needs distinct AF/VTE definitions and comparator handling.

Hard gates must cover legacy and downstream recommendation paths, use corrected normalization, and explicitly handle missing patient information.

**Phase 2 is the greatest evidence/calibration risk, not a mechanical follow-on.** Start with a small, fully reviewed vertical slice and release gates plus compatible ranking together. Broader taxonomy, generic rule machinery, and fallback frameworks can wait.

Factual verification here is limited to the supplied schema and aggregate statistics; the cited server implementation was not supplied for independent line-level verification.
